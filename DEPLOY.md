# Deploying Geo-rarity (Vercel + Supabase)

The game is a Next.js app (`app/`) on Vercel with a Postgres database on Supabase. The Python
pipeline never runs on Vercel: you run it from the dev container (or the GitHub Action) against the
Supabase database.

| Piece | Where it runs | How often |
|---|---|---|
| Game + API | Vercel | always |
| Nightly score settling (`/api/cron/finalize`) | Vercel Cron, 00:15 UTC | daily |
| Puzzle generation | GitHub Action or your dev container | weekly (keeps 30 days ahead) |
| Data refresh (`make data`) | your dev container | when you want new data |

## 1. Supabase

1. Create a project. Pick the region closest to most players and to your Vercel region.
2. **Database size:** the loaded data is about 270 MB, inside the free tier's 500 MB. Answers grow
   by roughly 1 KB per player per day.
3. In **Project Settings → Database**, copy two connection strings:
   - **Session pooler** (port 5432): for migrations, loading data and generating puzzles.
   - **Transaction pooler** (port 6543): for Vercel.
4. Download the **SSL certificate** from the same page (for `DATABASE_CA`).

## 2. Schema and data (from the dev container)

**Quickest: copy your local database.** One command creates the schema on Supabase and copies
everything the game needs (places, aliases, puzzles, practice pool, fact cards) from your local
database, but no players or answers, so the hosted game starts fresh:

```sh
make push-db DATABASE_URL='postgresql://postgres.<ref>:<password>@<host>:5432/postgres'
```

It refuses to run once the hosted game has players (so it can't replace live puzzles).

**Or build it from the pipeline output** with the session pooler URL:

```sh
export DATABASE_URL='postgresql://postgres.<ref>:<password>@<host>:5432/postgres'

make migrate                                         # creates the schema (pg_trgm, unaccent included)
make load LOAD_ARGS="--allow-unreviewed-flags"       # entities, aliases, relations from pipeline/out
make facts                                           # fact cards
make practice                                        # practice pool
make generate                                        # the next 30 days of puzzles
unset DATABASE_URL                                   # back to the local database
```

The load reads the Parquet files in `pipeline/out`, so run `make ingest` / `make popularity`
locally first if they're missing. Flag tags are still unreviewed: until `pipeline/flags_tags.yaml`
is reviewed, flag questions need `--allow-unreviewed-flags`.

## 3. Vercel

1. **Add New → Project**, import the GitHub repository, set **Root Directory** to `app`.
   The framework is detected as Next.js; keep the default build settings.
2. Environment variables (Production):

   | Name | Value |
   |---|---|
   | `DATABASE_URL` | Supabase **transaction pooler** URL (port 6543) |
   | `DATABASE_POOL_MAX` | `3` (each serverless instance keeps a small pool) |
   | `DATABASE_CA` | contents of the Supabase certificate (PEM; newlines may be written as `\n`) |
   | `ADMIN_TOKEN` | a long random string: the admin password |
   | `CRON_SECRET` | another long random string (Vercel sends it to the cron route) |

   `GAME_TODAY` is ignored in production. Don't set `ADMIN_RUN_PIPELINE` on Vercel: there is no
   Python there, so the admin's "regenerate" buttons stay off. Hand-written questions work.
3. Deploy. `vercel.json` registers the nightly cron (`/api/cron/finalize`, 00:15 UTC).
4. Log in to the admin once: `https://<your-domain>/api/admin/login?token=<ADMIN_TOKEN>`.

## 4. Keeping puzzles generated

Either:
- **GitHub Action** (`.github/workflows/generate-puzzles.yml`, Mondays 02:30 UTC): add the
  repository secret `DATABASE_URL` (session pooler URL) and the repository variable
  `ENABLE_PUZZLE_GENERATION` = `true`. It can also be run by hand from the Actions tab.
- **By hand**: `DATABASE_URL=... make generate` from the dev container, at least once every
  30 days.

Existing days are never regenerated by these runs, so published puzzles stay frozen.

## 5. Checks after deploying

- Open the site, play a question, open **Your stats**, **Practice**, **Privacy** and **Credits**.
- `curl -i https://<your-domain>/api/cron/finalize` must answer 403 (it needs the secret).
- Vercel → Project → Cron Jobs shows the finalize job; its first run is the next 00:15 UTC.
- The admin login link above opens the admin; without it `/admin` says "Not allowed".
